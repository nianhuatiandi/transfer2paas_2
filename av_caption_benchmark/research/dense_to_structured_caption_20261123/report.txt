Dense caption → structured caption / event graph 转换管线调研
调研日期：2026-11-23
范围：保留被测模型的原生提示词和输出，将输出文本统一解析为可审计的动作—人物—音频—时间关系结构。
状态：文献与公开代码静态审阅；未运行下载的第三方源码，未调用付费模型，未取得新实验分数。

一、结论

这条路线可行，相关基础也已经存在。“用 LLM 把 caption 变成 JSON”本身不是新贡献。最直接的前例是 OmniCapBench 的 post-hoc parsing；图像 caption 的 SPICE、FACTUAL、CAPTURE 则提供了文本到场景图的成熟路线。

对本项目更有意义的目标是：在不改变被测模型输出方式的情况下，忠实保留 caption 实际表达的人物、原子动作、专业细节、话语及其关系，且能够测出转换器自身造成的漏抽、增补和错误合并。

需要区分三种任务：
1. 语法适配：从原生 JSON、时间戳段落或自由文本读取内容；部分专用 captioner 本来就输出 JSON，困难不一定在 JSON 语法。
2. 语义解析：识别动作实例、参与者、限定词、指代、关系及原文证据。这是本次研究核心。
3. 视频重新理解：用视频、音频、ASR 或外部定位器补出原 caption 未包含的内容。这是额外系统能力，不能计入原 caption 模型表现。

三、建议的转换管线（设计方案，尚未实测）

原生模型输出
→ 确定性格式适配
→ 第 1 轮：声明、人物、动作、话语、声音抽取
→ 第 2 轮：实例消歧、专业术语归一与关系构建
→ 第 3 轮：文本证据与覆盖度审计
→ 确定性结构校验
→ 冻结候选事件图
→ 与细粒度 GT 匹配及分项评分

输入限制：parser 读取候选原文、原生输出自带时间、固定 schema、预先冻结的通用领域词表；不读取样本 GT、视频或音频。若允许额外提供 duration、镜头边界或字幕，必须记录来源并单独定义评测条件。

步骤 0：格式适配。
把原生 JSON/段落/时间戳段落转成 source_blocks，保存原始字符串及字符偏移。纯语法提取优先用规则，不让 LLM 改写原文。每块的时间范围只作为其容器时间；不能直接复制成块内每个子动作的真实起止时间。

第 1 轮：证据约束抽取。
为人物提及、动作提及、动作细节、话语和声音建立独立记录，保留引用原文及证据位置。动作可以拆成 actor、type、body_part、tool、target、manner、direction、result 等槽位；只填原文支持的槽位。
必须保留否定、可能性、尝试、条件、指令与引用的作用域。原 caption 的错误也要忠实保留，交由 scorer 判断，不能在这里纠正为“更合理”的动作。

第 2 轮：建图。
先解析人物指代，再区分动作实例。同词不等于同实例；相同实例的补充描述可以合并，但要保留多条证据。“挑了两次球”可以先保留 counted_event_group，不能凭空编造两次各自的细节和时间。
术语映射保存 raw_label、canonical_label、mapping_relation（equivalent / broader / narrower / ambiguous）。开放措辞仍保留，词表外内容不得直接丢弃。
不能因为“挑球”常常伴随迈步，就自动添加迈步；不能把“上前移动”升级为“并步”。
关系分为：事件先后/重叠/包含；音源和说话者；话语描述/指令所指的动作内容；可选因果与子事件。句子排列不是时间证据，“一边”通常支持重叠，不自动支持完全同时开始/结束。
同一句话提到某动作，不表示该话语与画面某次动作已绑定。若无法确认具体实例，保留未解析引用。

第 3 轮：双向审计。
图→原文：每个字段是否有充分证据？是否把不确定改成确定、把计划改成发生、把宽泛词改成专业细词？
原文→图：是否漏掉动作、重复次数、否定、说话者、声音或明确关系？
审计只能依据原文修复解析失真；不能为了提高分数删除原文确实说出的错误内容。
程序校验 ID 引用、证据偏移、数值单位、原生时间转换和关系冲突。原文自身矛盾应保留并标记，不能静默删边使图看起来一致。

四、推荐表示

source_blocks：不可变原文、原生时间及其来源。
entities：人物/物体实例与其 mentions；无法确定同一人时保留歧义。
events：动作、话语、声音；事件 ID、参与者、原始词、归一词、粒度、细节声明。
assertions：每条独立声明的 polarity、certainty、scope 和 evidence。
relations：source/target、类型、作用域、证据；明确区分原文直接陈述与逻辑推导。
time：explicit interval / explicit point / source segment container / unknown；保持原始精度。
unresolved：模糊指代、未绑定动作、未知时间、词表歧义；未知不得自动表示为 0。

动作事件和其细节声明应分层保存。一个跳跃可以有“摆臂”“双脚离地”等已描述子动作，但一个仅写了“跳跃”的预测不能自动覆盖所有 GT 子动作。

五、必须通过的边界案例

A. 原文：教练说“先并步再挑球”，队员没有移动。
   正确：保留真实话语事件；并步、挑球是话语内的指令内容；两者的 before 只在指令作用域内；移动为否定声明。
   错误：把队员的并步与挑球当成已发生动作，再声称完成音画对齐。

B. 原文：队员先并步，再挑球，随后再次挑球。
   正确：一个并步实例、两个挑球实例，以及明确顺序；全部没有秒级时间。
   错误：按动词去重成一个挑球，或自行分配 0–1 / 1–2 / 2–3 秒。

C. 原文：[0–7 s] 他完成了一次立定跳远。
   正确：一个跳远事件，来源段覆盖 0–7 s；动作精确边界未知。
   错误：补出未描述的预摆、蹬伸、腾空、落地，或把 0–7 s 当作每个阶段的定位。

D. 原文：他似乎先用左脚触地。
   正确：左脚、触地和“似乎”的不确定性同时保留。
   错误：转成确定的左脚落地事实，或通过运动常识改成双脚落地。

六、如何与细粒度 GT 评估而不奖励转换器编造

1. 分开评估文本解析质量与视频内容正确性。parser 的人工参考结构由标注员只看原 caption 建立；内容 benchmark GT 则来自视频，二者用途不同。
2. 固定一套 parser 用于所有模型；不因知道模型身份而换提示或修复规则。
3. 匹配先对齐人物和事件实例，再比较动作词、执行细节、话语和关系。重复事件使用实例级约束，不能由一条泛化预测获得多次完整命中。
4. 高层动作命中与细粒度细节命中分开；更一般的表达可以获粗粒度分，但未描述细节不得获分。
5. 语义、相对时序、音画指代/绑定、绝对时间分别报告。没有时间戳的模型仍可参加语义与相对时间评估；绝对时间评估要报告时间输出覆盖率，缺失不能从分母悄悄移除。不要填入 GT 时间。
6. GT 不一定穷尽所有真事实。候选新增声明应先标为未在 GT 找到支持，必要时人工核查；不能仅凭 GT 未收录就断言幻觉。
7. 不把 LLM 自报 confidence 当作经过校准的概率；是否可信需用人工标注校准。

七、验证实验与最小可行版本

建议先取 100–200 条原生 caption 做开发性 pilot，覆盖多个模型、领域和输出格式。这只是启动规模建议，不是论文充分性标准。
人工只看 caption 建立解析参考图，重点抽查：重复动作、双人指代、术语上下位、引用/否定、跨句先后、无时间戳和粗段时间。

转换基线：
B1. 单次 LLM，直接按固定 schema 抽取。
B2. OmniCapBench 的 post-hoc 思路适配；将仅 caption 与额外 shot_time 两种输入条件明确分开。
B3. FACTUAL/CAPTURE 静态元组抽取，仅比较其表达能力覆盖的子任务；不把其不支持的关系字段当成同等设置。
B4. 三轮证据审计的事件图解析。
B5. 人工解析同一候选 caption，作为转换质量参考。它不表示候选本身正确，也不保证任何评分器的数学上界。
另设直接 GT-checklist judge 作为评分协议对照；它与独立候选图的输入信息不同。

转换器指标：文本支持的预测声明比例、原文可表示声明覆盖率、人物与事件共指错误、重复实例合并错误、关系 F1、否定/作用域保持率、证据定位有效率。简单“证据字符串存在”不能证明该字符串蕴含输出声明。
系统指标：自动解析与人工解析所得模型排序差异；同义改写和格式变换下分数稳定性；否定翻转、主体交换、先后互换时能否检出错误；运行成本与重复调用稳定性。
消融：去掉证据审计、实例 ID、作用域、专业词表、上下文链接；观察各类错误，而非只看总分。
开发集定好提示、词表与阈值后冻结；在未参与开发的模型输出上检验，避免针对某种输出风格优化。

八、研究定位

可以形成的研究问题是：如何让原生自由输出与结构化输出的模型，在保留专业动作细节和音画时间关系的共同语义空间中被公平评估，并量化转换带来的测量误差？
潜在贡献要靠证据建立：专业动作与话语作用域 schema、原生 caption→结构的独立人工标注、可靠的转换协议，以及最终排序相对人工判断更稳定。单纯多轮 prompt、JSON schema 或组合现成 parser，不足以单独证明方法创新。
这份调研支持开展原型和标注 pilot；尚不能据此保证 ACL/ICML 录用，也没有证明建议管线优于现有方法。
